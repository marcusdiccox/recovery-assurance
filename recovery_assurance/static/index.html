Verification guide

How a drill is evaluated

  1. Capture a baseline. Save relative paths, byte sizes, and SHA-256 hashes from stable source data at backup time.
  2. Restore into isolation. Copy a directory snapshot or restore a restic snapshot into a fresh temporary directory.
  3. Compare every file. Flag changed, missing, and unexpected files. A matching size alone is insufficient.
  4. Check the time target. Measured time includes restore, verification, and cleanup. A run passes when integrity and its time target both pass.
  5. Record the result. Save evidence locally and export an HTML or JSON report. Temporary restored files are removed.

Scope of this check

Regular-file content and paths. Application startup, permissions, timestamps, database consistency, and recovery-point objectives are not checked.

Samples use synthetic files with real measured timings. The damaged snapshot and zero-second target deliberately demonstrate failures.
