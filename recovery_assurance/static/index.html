METHODOLOGY

What a verified recovery means.

  1. Capture a baseline. Save relative paths, byte sizes, and SHA-256 hashes from stable source data at backup time.
  2. Restore into isolation. Copy a directory snapshot or restore a restic snapshot into a fresh temporary directory.
  3. Compare every file. Flag changed, missing, and unexpected files. A matching size alone is never sufficient.
  4. Measure the objective. Recovery time includes restore and verification. A run passes only when integrity and its time target both pass.
  5. Keep the evidence. Store the result locally and export an inspectable report. Temporary restored files are cleaned up.

Scope: regular-file content and paths. This does not validate application startup, permissions, timestamps, database consistency, or recovery-point objectives. A local file drill does not certify disaster recovery. Sample drills use synthetic files with real measured timings, including one deliberately damaged snapshot and one deliberately impossible 0-second target.
